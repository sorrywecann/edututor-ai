5-min test recipe

  1. Otvor localhost:3000/avatar-debug v prehliadači
  2. Pripoj svoj Blueprint na ws://localhost:8000/ws/avatar
  3. Verify pill v pravom hornom rohu zobrazí IDLE — backend heartbeat alive
  4. Rozbal "🛠 Inject avatar command" → vyber preset → klikni Inject
  5. Pozri Blueprint reakciu na payload — bez chat triggeru, bez TTS, bez LLM
Presets na vyskúšanie
  • Idle — pasívne pozeranie
  • Speaking (aa viseme) — otvorené ústa, viseme path
  • Joy speaking — emotion + viseme spolu
  • agentState: searching — testuje v2.1 idle state machine
  • ARKit frame (JawOpen) — testuje v3.0 blendshape mapping

v2.0 — baseline

v2.0 Pôvodný protokol (ak nemáš, začni tu)
EMOTION · INTENSITY · ISSPEAKING · VISEMES · BLINK · VISEME_TIMELINE · TOTAL_DURATION_MS

JSON payload shape

{
  "emotion": "joy",
  "intensity": 0.9,
  "isSpeaking": true,
  "visemes": [{"viseme": "aa", "weight": 0.9}],
  "blink": 0.0,
  "viseme_timeline": [
    {"viseme": "PP", "weight": 1.0, "start_ms": 0,  "duration_ms": 80},
    {"viseme": "aa", "weight": 1.0, "start_ms": 80, "duration_ms": 120}
  ],
  "total_duration_ms": 2400
}

Blueprint nodes (minimum viable)

  1. WebSocket node → connect to ws://localhost:8000/ws/avatar
  2. OnConnected → send handshake {"type":"avatar_ready","capabilities":["viseme","emotion","state"]}
  3. OnMessage → JSON parse → branch on parsed.type:
    • type=="connected" → log, ignore
    • else (per-frame command):
      • Lerp emotion blendshape (200–300ms blend time)
      • Lerp current viseme blendshape (80–100ms)
      • If viseme_timeline present → start timeline scrub
  4. Emotion → State Machine v AnimBP (9 states: neutral/joy/proud/encouraging_mild/sadness/patient/curious/thinking_deep/surprise)
  5. Viseme → Blendshape mapping (14 Slovak visemes: sil/aa/oh/ou/ih/E/PP/FF/DD/nn/SS/CH/kk/RR)
  6. Auto-blink — local Blueprint ticker, every 3–6s, ignore blink field if 0.0

Reference TypeScript: useUE5Bridge.ts — same logic in JS form (we send, you receive).

v2.1 — agentState P1

v2.1 Idle state machine
PHASE 6A · 2026-05-07 · OPTIONAL FIELD · BACK-COMPAT GUARANTEED

Čo sa zmenilo

Pridané jedno optional pole: agentState (string).

{ "emotion":"thinking_deep", "intensity":0.6, "isSpeaking":false,
  "visemes":[{"viseme":"sil","weight":1.0}], "blink":0.0,
  "agentState":"searching"   ← NOVÉ
}

Hodnoty (5 stavov)

StateKedyIdle animácia (návrh)
IDLEDefault, nečinný stavSubtle breathing, occasional blink
THINKINGLLM premýšľa nad odpoveďouLook up-left, slight head tilt
SEARCHINGTool dispatch (web search, KB)Eyes scan left-right, faster blink
WRITINGGenerovanie textuSubtle head nod, focused stare
LISTENINGUser hovorí, mikrofón aktívnyLean forward, attentive
Back-compat Keď backend neposiela agentState, pole je úplne vynechané z JSON. Tvoj v2.0 Blueprint, ktorý JSON Parse Object → Get Field "agentState", dostane null a tichá vetva ho ignoruje. Žiadna zmena nie je potrebná pre v2.0 chat traffic. Pinné v test_ws_avatar.py:412-475 (3 testy).

Čo pridať do Blueprintu

  1. AnimBP State Machine s 5 stavmi (idle / thinking / searching / writing / listening)
  2. Transition rule — read agentState na každom incoming payload, set as enum/string variable, transition based on it
  3. Idle pose v každom state — môže byť rovnaký rig, len iná blendshape preset
  4. Default fallback — keď agentState chýba alebo má neznámu hodnotu, transition na idle
BLUEPRINT PSEUDOKÓD
OnMessage(json):
  agentState = json.Get("agentState")          // string or null
  IF agentState IS VALID STRING:
    SET CurrentAgentState = agentState         // AnimBP var
  ELSE:
    SET CurrentAgentState = "idle"
  // ... continue existing emotion/viseme logic

Test recipe

  1. Otvor localhost:3000/avatar-debug
  2. Pripoj svoj Blueprint na ws://localhost:8000/ws/avatar
  3. Rozbal Inject panel, vyber agentState: searching preset, klikni Inject
  4. Tvoj Blueprint má prejsť do SEARCHING idle animácie. Pill v rohu ukáže SEARCHING.
  5. Vyber preset Idle → návrat do IDLE

v3.0 — ARKit P1

v3.0 52-channel ARKit blendshapes
PHASE 5+ · AUDIO2LIPSYNC INTEGRATION · LIVELINK POSE ASSET RECOMMENDED

Čo sa zmenilo

Pridané dve nové polia: arkit (per-frame snapshot) a arkit_frames (timeline).

{ "emotion":"neutral", "intensity":0.4, "isSpeaking":true,
  "visemes":[{"viseme":"sil","weight":1.0}],     ← visemes ostávajú, ale ignoruj v ARKit mode
  "arkit": {                                       ← NOVÉ snapshot
    "JawOpen": 0.31,
    "MouthFunnel": 0.12,
    "MouthSmileLeft": 0.08
  },
  "blink": 0.0,
  "arkit_frames": [                                ← NOVÉ timeline
    {"start_ms": 0,  "duration_ms": 16, "arkit": {"JawOpen": 0.02}},
    {"start_ms": 16, "duration_ms": 16, "arkit": {"JawOpen": 0.18, "MouthFunnel": 0.12}}
  ]
}

Mode detection

IF parsed.Get("arkit") IS VALID OR parsed.Get("arkit_frames") IS VALID:
  ARKitMode = TRUE                          // use 52-channel blendshapes
ELSE:
  ARKitMode = FALSE                         // use 14-viseme path (v2.0)
Channel naming (CRITICAL — najčastejší Blueprint bug) Náš model produkuje PascalCase mená kanálov, presne podľa iPhone Live Link Face format:
EyeBlinkLeft, JawForward, JawRight, JawLeft, JawOpen, MouthClose, MouthFunnel, MouthSmileLeft, MouthSmileRight, BrowInnerUp, ... Plný 52-kanálový zoznam: audio2lipsync/constants.py:23-57. Pinné v teste test_arkit_channel_names_are_pascalcase.

Dve cesty implementácie

Cesta A — LiveLink Pose Asset (odporúčaná)
  1. Použi MetaHuman default Pose Asset mh_arkit_mapping_pose (Asset Browser → Faces → Source Assets)
  2. Vytvor Custom LiveLink Source (Plugins → Live Link → Add → Custom)
  3. Push 52-channel float pole každý frame
  4. Pose Asset automaticky mapuje PascalCase → MetaHuman Control Rig curves (CTRL_expressions_jawOpen, atď.)
  5. Žiadne manuálne mapovanie!
Cesta B — Manuálny SetMorphTarget
  1. Iteruj cez arkit dict
  2. Pre každý key v PascalCase → namapuj na MetaHuman morph target naming (camelCase first letter lower):
    • JawOpen → jawOpen
    • MouthSmileLeft → mouthSmileLeft
    • EyeBlinkLeft → eyeBlinkLeft
  3. Volaj SkeletalMeshComponent.SetMorphTarget(target_name, value)
Pre prvý pokus odporúčam Cestu A. Zaberie 30 minút setup, ušetrí hodiny debuggingu mapping bugov.

Timeline scheduling (60fps)

arkit_frames je per-sentence pre-queued. Každá veta posiela kompletný array frames vopred. Tvoj Blueprint má:

  1. Snapshot frames keď príde nový payload s arkit_frames
  2. Schedule každý frame proti audio clock (NIE proti Blueprint Tick — pozri v4.0)
  3. Apply ARKit dict na blendshapes pri scheduled time
  4. Threshold pruning — len kanály s value > 0.005 sú v payload. Chýbajúce kanály = 0.0 (lerp z aktuálnej hodnoty späť na 0)

Test recipe

  1. Inject panel → preset ARKit frame (JawOpen) → Inject
  2. Tvoj MetaHuman by mal otvoriť ústa (JawOpen=0.31) + zatlačiť pery (MouthFunnel=0.12)
  3. Po ~50ms relax späť na neutral
  4. Ak sa nič nedeje: skontroluj (a) ARKitMode detection (b) PascalCase mapping (c) Pose Asset wiring

v4.0 — audioPositionMs + sentenceIdx P2

v4.0 Sender-supplied audio clock
PHASE 7 · 2026-05-08 · PER-FRAME · REPLACES SELF-TIMING DRIFT

Čo sa zmenilo

Frontend pošle na každom rAF tick dve nové polia kým je isSpeaking=true:

{ "emotion":"joy", "intensity":0.9, "isSpeaking":true,
  "visemes":[{"viseme":"aa","weight":0.9}],
  "blink":0.0,
  "audioPositionMs": 1280,   ← NOVÉ — ms od začiatku lipsync (browser AudioContext clock)
  "sentenceIdx": 2           ← NOVÉ — ktorá veta v multi-sentence chat odpovedi
}

Prečo je toto dôležité

Doteraz si v Blueprint timeline scruboval vlastným tickerom — Blueprint Tick alebo Set Timer by Function Name. To má drift: 16ms tick + audio device latency + frame variability = až 100ms desync na konci dlhej vety.

S v4.0 sender ti pošle presnú audio pozíciu. Tvoj Blueprint scrubuje proti tomu, nie proti vlastným hodinám.

BLUEPRINT PSEUDOKÓD
audioPositionMs = parsed.Get("audioPositionMs", -1)
sentenceIdx     = parsed.Get("sentenceIdx",     -1)

IF audioPositionMs >= 0:                     // v4.0 client
  IF sentenceIdx != LastSentenceIdx:
    LastSentenceIdx = sentenceIdx
    // Reset interpolation state, swap timelines
  frameStepMs = ActiveTimeline[1].start_ms - ActiveTimeline[0].start_ms  // dynamic, server default 40ms since 2026-05-12 (was 8ms)
                                                                          // for arkit_frames: use frame's duration_ms (~16ms @ 60fps)
  idx = Clamp(Floor(audioPositionMs / frameStepMs), 0, Len(ActiveTimeline)-1)
  ActiveFrame = ActiveTimeline[idx]
  ApplyFrame(ActiveFrame)
ELSE:                                         // v3.0 or older client fallback
  // Keep your own ticker logic for old browsers
Reference implementácia TypeScript verzia tohto algoritmu žije v core/src/app/(shell)/avatar-debug/simulator/page.tsx:49-68. Komentár v kóde explicitne hovorí "this page IS the Blueprint reference." Otvor localhost:3000/avatar-debug/simulator a pozri ako to scrubuje vizuálne.
⚠ Viseme frame step zmenený: 8ms → 40ms (2026-05-12) Roland nahlásil že 8ms grid pôsobí na MetaHumanovi ako rýchle prskanie. Bumpli sme default na 40ms (jeho dolný odhad pre prirodzenú reč). Tunable cez EDU_VISEME_FRAME_STEP_MS env var (range 4-200ms).

Čo to znamená: Ak frameStepMs derivuješ z timeline[1].start_ms - timeline[0].start_ms (ako simulátor + frontend), nič nemusíš robiť — auto-adaptuje sa. Ak máš zahardcodované frameStepMs = 8, Floor(audioPositionMs/8) vráti index mimo array a Blueprint zamrzne na poslednej frame. Fix: jedna riadka — nahraď konštantu derivátom z timeline.

ARKit cesta nezmenená: arkit_frames má 60fps (~16ms) ako predtým. Toto sa týka iba viseme cesty.

Benefit

  • Drift < 50ms aj na slabých browseroch
  • Žiadny custom ticker v Blueprinte
  • Sentence boundary detection cez sentenceIdx zmenu → reset interpolation pri každej novej vete

Test recipe

  1. Pošli reálnu chat správu z chat UI (localhost:3000)
  2. Pozri /avatar-debug live log — uvidíš payloads s audioPositionMs: 0, 16, 32, ...
  3. Tvoj Blueprint by mal scrubovať lipsync presne s audio — bez drift na konci vety
