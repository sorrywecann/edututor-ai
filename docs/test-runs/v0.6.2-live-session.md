## What broke

### Bug #1: `hf_xet` missing in bundle

**Severity:** P1 (voice input completely broken until fixed)

**Root cause:** Bundled `huggingface_hub` v1.17.0 uses **Xet** storage as the default download path. The required `hf_xet` Python package is NOT in the bundle. When backend tries to download `faster-whisper-small` on first STT call, it crashes with:
```
RuntimeError: faster-whisper init failed: To use optimized download using Xet storage,
you need to install the hf_xet package.
```

**Inline workaround (already applied):** copied `~/.cache/huggingface/hub/models--Systran--faster-whisper-small` → `<userData>/hf-cache/hub/` (924.8 MB). Backend respawned, STT now works.

This workaround is **temporary** — every fresh install on a clean Windows machine without that host cache will hit the same bug.

## Fix plan for v0.6.3

**Three options, ranked:**

### Option A — Pre-bake faster-whisper-small in bundle (RECOMMENDED)
**What:** `stage-resources.mjs` already copies MiniLM (458 MB). Add a step to also copy `models--Systran--faster-whisper-small` (~244 MB). Total HF cache: 458 + 244 = 702 MB → installer ~1.1 GB.

**Pros:**
- Offline-capable (zero HF network on first launch)
- Avoids Xet entirely (no `hf_xet` needed)
- Same pattern as MiniLM (proven)
- ~244 MB extra in installer, acceptable

**Cons:**
- Installer grows 886 MB → ~1.1 GB

### Option B — Ship `hf_xet` in bundle
**What:** Add `hf_xet` (a Rust-backed Python wheel) to bundled site-packages.

**Pros:**
- ~5 MB extra (tiny)
- Future-proof (works for any HF model)

**Cons:**
- Still requires HF network on first launch (slow)
- Extra moving part (Rust wheel)

### Option C — Disable Xet via env var
**What:** Set `HF_HUB_DISABLE_XET=1` or similar before backend spawn.

**Pros:**
- 0 byte cost

**Cons:**
- Not confirmed this env var exists in HF Hub 1.17.0 (need to test)
- May break in next HF Hub version

**Decision:** **Option A** for v0.6.3. Same pattern, deterministic, no network dep, matches our pre-baked MiniLM strategy.
