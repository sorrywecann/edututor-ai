## Then test the actual voice loop bug

This is what we've been hunting since v0.5.5.

1. App fully ready, all 5 ports green
2. Open DevTools: **Ctrl+Shift+I** -> Console tab
3. Right-click in Console -> Clear console
4. Click orb -> speak "Aky je hlavny mesto Slovenska"
5. Wait for response to play and finish
6. **DO NOT touch anything for 10 seconds**
7. Orb should AUTOMATICALLY return to listening
8. Then speak "A Ceske"
9. Should respond without you clicking

### Console transcript

Copy DevTools Console contents (Ctrl+A, Ctrl+C in Console pane) into:
```
docs/test-runs/v0.6.3-voice-console.log
```

Expected good-path markers (in order):
```
[voice] session START
[voice] stream END  (queueLen=N playing=BOOL active=BOOL)
[voice] queue empty + stream done — restarting listener  (active=true)
```

If the third line never appears, the voice loop bug is still present.
Other diagnostic lines we'll see:
- `[voice-watchdog] RESCUE  idle stalled 5000ms ...`  -> self-heal kicked in (acceptable)
- `[voice] audio safety timeout fired after Xms`     -> onended ghost-drop (bug pattern)
